# QTimer 정답 위험도 QA

업데이트: 2026-08-11

## 목적

문제은행 973문항의 구조 QA가 통과한 뒤, 모든 문항을 동일한 비용으로 다시 검토하지 않고 **정답 오류 가능성이 높은 문제를 우선순위로 추출**한다.

정답 위험도 QA는 문제를 삭제하거나 정답을 자동 변경하지 않는다. 검토 순서를 정하는 비차단(non-blocking) 큐다.

## 실행

```bash
node scripts/audit-answer-risk.mjs --summary
node scripts/audit-answer-risk.mjs --limit=80
```

`bash scripts/check-wsl.sh`는 `--summary` 모드로 Gate 3를 자동 실행한다.

## 위험도 분류

### P0
점수 8 이상. 원본 이미지와 독립 풀이를 가장 먼저 대조한다.

### P1
점수 6~7. P0 검토 후 확인한다.

### P2
점수 4~5. 계산·알고리즘·암호 등 일반 개념형보다 오답 위험이 높은 문제를 포함한다.

## 가중치

- 실제 C/Java/Python 코드 실행: +5
- 실제 SQL 질의/서브쿼리/집합 SQL 실행: +5
- CIDR/서브넷/브로드캐스트 계산: +5
- 스케줄링·페이지 교체·메모리·COCOMO·FP·CPM 등 계산: +4
- 암호/보안: +3
- 원본 도표/실행 결과 의존: +3
- 선택지가 이미지/결과 표시에 의존: +3
- `verificationStatus=auto_matched`: +1
- `extractionStatus=READY_PARAPHRASE`: +1
- 매우 짧은 해설: +1
- 정답 출처 불일치: +10

단순히 문장에 `실행 결과`가 있거나 관계대수의 Select/Project가 있다는 이유만으로 코드/SQL 위험군에 넣지 않는다. 네트워크 계산도 일반적인 `/숫자` 문자열이 아니라 IPv4/CIDR·서브넷 문맥이 있어야 한다.

## 검증 절차

P0부터 다음 순서로 검증한다.

1. `sourceImageUrl` 원본 이미지의 문제번호와 하단 정답 확인
2. 문제문·선택지 구조화가 원본 의미를 유지하는지 확인
3. **QTimer 문제문만으로 독립적으로 풀 수 있는지 확인**
4. 교재 정답과 무관하게 문제를 독립적으로 다시 풀이
5. 독립 풀이 결과와 `sourceAnswer` 비교
6. 일치하면 `independentVerified=true`, 날짜, 근거를 기록
7. 불일치하면 `needs_review` 또는 `source_error_suspected`로 전환
8. 정답 변경 시 기존 `sourceAnswer`를 덮어쓰지 않고 검증 이력을 보존

독립 검증된 문제는 위험 점수가 높더라도 다음 실행의 **미검증 큐에서는 제외**하고 별도 `Independently verified risk items` 수치로 집계한다.

## 문항 완전성(Self-contained) QA

정답 번호가 맞더라도 다음 상태는 품질 오류로 본다.

- `다음 표`라고 되어 있으나 표 데이터가 문제문에 없음
- SQL/코드가 다음 페이지로 이어지는데 현재 레코드에 뒤쪽 내용이 없음
- 선택지가 `①의 결과`, `②의 결과`처럼 원본 이미지 없이는 의미를 알 수 없음
- 계산에 필요한 숫자/도표가 구조화 과정에서 누락됨

발견 시 원본을 보존하면서 별도 quality override에서 문제문·선택지를 self-contained 형태로 보완한다.

## 운영 원칙

- Gate 1: 973문항 수량·기본 무결성 — blocking
- Gate 2: Chapter/ID/원본/중복 구조 QA — blocking
- Gate 3: 정답 위험군 우선순위 — non-blocking
- P0 검증 완료 후 P1, 그 다음 P2 순서
