# QTimer 기획 요약

기준일: 2026-08-11
상태: v0.1 구현 전 기획 스냅샷

## 1. 제품 목적

QTimer는 단순 스톱워치나 문제은행이 아니라, 기출문제를 빠르게 분류하고 취약문제를 압축하여 반복하는 **시험 대비 훈련 시스템**이다.

핵심 루프:

`문제 → 시간 측정 → 답 입력/채점 → 확신도 → 취약분류 → 반복회독 → 숙달`

기본 원칙:

- 학습 중 UI 조작을 최소화한다.
- 키보드 중심, 특히 SPACE를 핵심 입력으로 사용한다.
- 정답률만 보지 않고 정오·확신·시간을 독립적으로 기록한다.
- 회독이 진행될수록 취약문제 집합이 줄어드는 구조를 만든다.
- 시험 직전에는 새로운 내용을 늘리기보다 반복오답·모름·애매·시간초과를 압축한다.

## 2. 핵심 Workspace

### Learn Workspace
- 왼쪽: 문제
- 오른쪽: 풀이 결과, 핵심, 문제집 해설, AI 해설, 사용자 메모
- 답 제출 전 해설은 숨긴다.
- 답 제출 후 정답/오답/애매/시간 상태와 해설을 보여준다.

### Exam Workspace
- 왼쪽: 문제
- 오른쪽: 전체 답안표
- 문제 선택지와 답안표는 동일한 답안 상태를 공유한다.
- 왼쪽에서 선택하면 오른쪽에 즉시 반영되고, 오른쪽에서 선택해도 왼쪽에 반영된다.

## 3. 주요 모드

- 빠른 회독
- 학습
- 문제풀이
- CBT 모의고사
- 취약 집중

화면은 Learn/Exam 두 Workspace를 재사용하고, 모드에 따라 채점 시점과 타이머 정책만 바꾼다.

## 4. 문제 상태 3축

### 정오
- 정답
- 오답
- 모름/미응답

### 확신
- 확실
- 애매

### 시간
- IN
- OVER / TIME OUT

예: `정답 + 애매 + OVER`도 가능하며 숙달로 보지 않는다.

## 5. 타이머 정책

- No Limit: 제한 없음
- Soft Limit: 제한시간 초과 경고 후 계속 풀이
- Hard Limit: 제한시간 초과 시 TIME OUT 기록 후 자동 다음 문제

기본값:
- 빠른 회독: Hard Limit
- 취약/학습: Soft Limit
- 모의고사: 문제별 강제 제한 없음, 전체 시험시간만 사용

시간초과는 오답과 별개 상태다.

## 6. 숙달

기본 숙달 규칙:

`2회 연속 정답 + 두 번 모두 확실 + 두 번 모두 목표시간 이내 → MASTERED`

애매한 정답은 숙달로 처리하지 않는다.

## 7. 취약 우선순위

우선 검토 대상:

1. 반복오답
2. 확실하게 틀린 문제
3. 모름
4. 최근 오답
5. 애매
6. 정답이지만 느린 문제

빠르고 확실하게 맞힌 문제는 당분간 회독에서 제외한다.

## 8. 문제 유형

- single_choice
- multiple_choice
- true_false
- cloze
- short_answer
- subjective

빈칸 문제는 핵심어 회상, 정의, 비교·구별, 순서·절차에 활용한다.

## 9. 해설 구조

서로 섞지 않고 별도 보관한다.

- 핵심 / FINAL KEY
- 문제집 해설
- AI 해설
- 구별 포인트
- 사용자 메모

오답/애매 문제에 대해서는 필요에 따라 AI가 빈칸 문제와 변형문제를 생성한다.

## 10. 사용자 표시 설정

사용자가 다음을 조정할 수 있도록 설계한다.

- 글꼴
- 문제/선택지/해설 글자 크기
- 굵기
- 줄 간격/자간
- 선택답/정답/오답/애매/핵심어/FINAL KEY 형광펜 색
- 배경형/밑줄형 강조
- 기본/형광펜/고대비/눈 편한/야간 프리셋

색상 외에도 아이콘과 텍스트를 병행한다.

## 11. 데이터/문서 역할

- Google Drive: 문제·정답 원본 사진
- Google Sheets: 문제은행, 정답, 풀이기록, 상태, 검증 Queue
- Google Docs: 사람이 읽는 취약문제 해설집
- QTimer 브라우저: 타이머, 현재 세션, 로컬 즉시 저장

## 12. 사진 문제화

목표 흐름:

`Drive 사진 → AI Vision 구조화 → 필요시 OCR 보조 → 문항 분리 → 정답 매칭 → 검증 → Sheets → QTimer`

원본 사진은 항상 보존하고 각 추출 문제와 연결한다.

## 13. 정답 검증

정답은 하나로 덮어쓰지 않는다.

- source_answer
- ai_detected_answer
- ai_reasoned_answer
- user_verified_answer
- effective_answer

정답지와 AI 판단이 다르거나 신뢰도가 낮은 문제만 검증 Queue로 보내 사용자가 확인한다.

정답 변경 이력은 보존하며, 최종 정답 변경 시 과거 Attempt를 재채점할 수 있어야 한다.

## 14. v0.1 운영 원칙

시험 준비에 직접 필요한 기능만 구현한다.

새로운 아이디어는 먼저 Backlog에 기록하고 다음에만 v0.1 변경을 허용한다.

- 데이터 손실
- 채점 오류
- 핵심 학습 흐름이 작동하지 않음
- 실제 시험 대비를 방해하는 심각한 UX 문제

그 외 아이디어는 v0.2 이후로 미룬다.
